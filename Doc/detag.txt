Le DETAG et Manipulation de NFO : Les pratiques interdites

Quatre types, des sanctions, et comment ne pas se faire prendre par mégarde.
En une phrase

Détaguer une release, c'est retirer ou remplacer le tag d'origine d'une équipe ou d'un releaser, puis remettre le fichier en partage sans cette signature. C'est interdit sur C411. Il existe quatre types de DETAG, classés par gravité.

Pourquoi c'est interdit

    Respect du travail : le tag est la signature de la personne ou de l'équipe qui a fait le rip, l'encode ou la traduction. Le retirer revient à effacer leur identité.

    Cohérence du tracker : sans tag commun, on ne peut plus repérer les doublons, et le cross-seed entre trackers casse.

    Confiance communautaire : les équipes qui voient leurs releases redistribuées sans crédit refusent ensuite de venir sur le tracker. C'est tout le monde qui perd au change.

1. DETAG de filename

Définition : le titre du torrent porte un tag d'équipe, mais aucun fichier media du torrent ne le porte. À 99% le signe d'un fichier renommé manuellement (souvent par une stack

*arr

ou un copier-coller maladroit).

Exemple flagrant :

    Titre :

    Movie.2024.MULTI.VFF.1080p.BluRay.x264-TFA

    Fichier dans le torrent :

    Movie.2024.mkv

    (sans

    -TFA

    à la fin)

Comment éviter l'erreur : avant d'uploader, renommez chaque fichier media pour qu'il finisse par le tag d'origine. Si vous utilisez une stack *arr (Sonarr, Radarr) qui renomme automatiquement, vérifiez le pattern de renommage et ajoutez le tag à la fin.

Sanction : 1ère fois → message éducatif. Récidive → perte du statut certifié et ban upload temporaire.

2. DETAG de cohérence

Définition : un tag est présent à plusieurs endroits (titre, NFO, fichiers) mais ils ne sont pas cohérents entre eux. C'est un vol d'identité multi-sources : l'uploader prétend qu'une release vient d'une équipe alors que les preuves disent autre chose.

Exemple flagrant :

    Titre :

    Movie.2024.MULTI.VFF.1080p.BluRay.x264-MyTeam

    NFO contient :

    Release : TFA

    Fichier dans le torrent :

    Movie.2024.MULTI.VFF.1080p.BluRay.x264-TFA.mkv

Dans cet exemple, deux sources sur trois disent

-TFA

. Le titre

-MyTeam

est manifestement incohérent.

Cas particulier : si le titre porte un tag d'une source de DETAG connue (Wawacity par exemple) ou d'une équipe bannie (k0RE), c'est bloqué directement sans même comparer aux autres sources.

Comment éviter l'erreur : alignez le tag entre titre, NFO et fichiers. Si vous récupérez un fichier d'une autre source, conservez le tag d'origine.

Sanction : perte du statut certifié + ban upload temporaire. Récidive → ban upload prolongé.

3. DETAG par omission (NOTAG)

Définition : le titre prétend

-NOTAG

(release sans équipe identifiable) mais une autre source porte un tag d'équipe identifiable. À 99% un effacement de signature par paresse.

Exemple flagrant :

    Titre :

    Knuckles.S01E01.MULTI.1080p.PMTP.WEB-DL.DDP2.0.HDR.H265-NOTAG

    NFO contient :

    Release : TFA

    Fichier dans le torrent :

    Knuckles.S01E01.MULTI.1080p.PMTP.WEB-DL.DDP2.0.HDR.H265-TFA.mkv

L'uploader savait que c'était une release TFA et a quand même mis NOTAG dans le titre. Effacement délibéré.

NOTAG légitime :

-NOTAG

est valide uniquement quand aucune équipe d'origine n'est identifiable. Dans ce cas,

NOTAG

doit apparaître partout : titre, NFO et nom des fichiers media. Si vous remettez en partage un vieux fichier sans NFO sans nom d'équipe, c'est un cas légitime.Comment éviter l'erreur : ne mettez

-NOTAG

que si vous avez vraiment cherché et n'avez rien trouvé. Si vous trouvez le tag d'origine, utilisez-le.

Sanction : perte du statut certifié + ban upload temporaire. Récidive → ban upload prolongé.

4. DETAG RETAG (le crime)

Définition : l'uploader remplace volontairement le tag de l'équipe d'origine par son propre pseudo, dans le but de s'approprier le mérite du travail. C'est le DETAG le plus grave car il y a intention claire d'attribuer à soi le travail d'un autre.

Exemple flagrant :

    Titre :

    Film.2024.MULTI.VFF.1080p.BluRay.x264-MonPseudo

    NFO contient :

    Release : Slay3R

    Fichier dans le torrent :

    Film.2024.MULTI.VFF.1080p.BluRay.x264-Slay3R.mkv

Le NFO et le fichier portent tous les deux

Slay3R

. L'uploader a juste remplacé le tag dans le titre par son pseudo. Vol d'identité caractérisé.

Comment éviter l'erreur : il n'y a pas d'excuse. Si vous repostez le travail d'une autre équipe, gardez son tag. Si vous voulez créer votre propre release, refaites un encode différent et signez-le proprement.

Sanction : ban tracker. Pas de seconde chance.

Cas particuliers à connaître

Source pure BDMV ou ISO : aucune signature dans les fichiers

.m2ts

,

.bdmv

ou

.iso

. C'est normal et le système ne flag pas

NOTAG

ou DETAG de filename dans ce cas.Encode personnel sans tag d'origine retrouvable : si vous avez un fichier ancien sans NFO et sans nom d'équipe identifiable, vous pouvez publier en

-NOTAG

à condition d'ajouter aussi

-NOTAG

au nom des fichiers pour cohérence.Sous-types de codec audio (

AAC-LC

,

DTS-HD MA

,

AAC-HE

) : ce sont des spécificités techniques du codec, pas des tags d'équipe. Le moteur les ignore.Tirets internes au nom d'équipe (

Tsundere-Raws

,

WEB-DL

) : reconnus par normalisation. Pas de faux positif.

Bypass certifié

Pour les uploaders certifiés dans la catégorie du torrent, les avertissements de sévérité moyenne (1 seule source contredit, cas ambigu) deviennent non bloquants : vous pouvez passer outre en fournissant une justification courte. La justification est ajoutée au dossier de votre upload pour la Team Pending.

Les blocages de sévérité haute (plusieurs sources concordent, ou tag explicitement classé comme DETAG) restent en vigueur pour tout le monde, sans bypass possible. Ils correspondent à des cas où il n'y a pas d'ambiguïté.

Si vous pensez être bloqué à tort

    Vérifiez que votre titre, le NFO et les noms de fichiers utilisent le même tag.

    Si la source est un BDMV ou ISO sans NFO scène, mettez

    -NOTAG

    partout.

    Si vous êtes vraiment le releaser et que le tag n'est pas reconnu, ouvrez un ticket Support pour faire ajouter votre tag au référentiel par la Team Pending.

Pour la Team Pending

Le référentiel des tags connus est consultable et modifiable depuis le dashboard Team Pending : /team-pending/known-tags. Cinq catégories possibles : Team interne, Scène, P2P externe, Détag connu, Bannie. Au démarrage, le référentiel est volontairement réduit (politique zéro faux positif). Étoffez-le au fil des signalements et discussions team-pending.

Les signaux post-upload sont consultables sur /team-pending/detag-signals. Vous pouvez confirmer ou rejeter chaque signal. Confirmation incrémente le compteur de détags 90 jours sur le profil de l'uploader. Rejet sauvegarde le cas dans le corpus de faux positifs pour calibrer les prochaines itérations du moteur.
